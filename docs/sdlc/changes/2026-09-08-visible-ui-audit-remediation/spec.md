# Spec: 可见界面修复验收

## Design

沿现有组件和语义 token 修复根因。同类问题优先修共享边界；页面级信息结构保留功能和数据契约。现有原生截图证明症状，测试证明交互/计算，实际窗口证明布局。统计与权限文案必须反映真实行为，不能仅用换词遮盖失败。审美建议按可读性和效率落实，不做无关重设计。

## Acceptance criteria

- [x] AC-1: 共享窗口、面板和工作区：默认和窄窗口下，面板内容、文件编辑器和内置网页不被横向裁切；对话具有可用阅读宽度。
- [x] AC-2: 任务导航与弹窗：任务总控能通过关闭按钮和 Esc 退出；同名搜索结果可区分且仅一个选中。
- [x] AC-3: 终端：显示、隐藏、切换工作区和尺寸变化不重复处理相同尺寸，不重复绘制提示符；空闲终端生命周期可说明。
- [x] AC-4: 看板与任务表单：看板可收起检查器、列表状态和日期不碎行，详情、洞察和新任务术语一致。
- [x] AC-5: PR 与自动化：PR 文件名和检查来源可辨认；自动化状态、失败反馈和时间表达清晰。
- [x] AC-6: 插件：零缺失不报错；空态区分未配置与无匹配，并提供真实可行的下一步；市场按钮与行为一致。
- [x] AC-7: 设置基础与统计：通用、导入、Profile、外观、宠物、快捷键、用量的文案、预览、统计口径和布局与实际行为一致。
- [x] AC-8: 工作区与集成设置：项目、Worktree、记忆、同步、供应商、Computer Use、Appshots、Browser Use、浏览器、开发者页状态和操作范围明确，记忆统计不溢出。
- [x] AC-9: 场景编辑：选择器、场景库和七个编辑页签可检查配置；表单避免不必要的标识符手输，错误可定位，JSON 编辑区域可用。
- [x] AC-10: 辅助面板和弹窗：轨迹、两种临时对话、设备连接、Issue、搜索、文件引用、项目动作和环境显示的作用与状态清楚。
- [x] AC-11: 验证与清理：每项完成状态都有对应检查证据；受影响界面进行实际渲染，清理与保留资源具有明确归属。
